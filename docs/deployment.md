# Deployment runbook

Fresh deploy of the shielded borrow pool to a Stellar testnet. Reuse
the recipe against public/futurenet by swapping `--network` + endpoint
env vars.

## Prerequisites

- `stellar` CLI (Soroban SDK 22.0.x compatible)
- `bun` toolchain
- A funded testnet keypair identity: `stellar keys generate deployer --network testnet && stellar keys fund deployer --network testnet`
- Reflector CEX + FX contract IDs for the target network (defaults ship
  in `.env.example`)
- SEP-41 token contracts for every shielded asset (XLM native SAC on
  testnet is `CDLZFC3SYJYDZT7K67VZ75HPJVIEUVNIXF47ZG2FB2RMQQVU2HHGCYSC`;
  USDC/EURC via the Reflector-side registered token contracts)

## Step 1 — Build + upload wasm

```bash
cd contracts
stellar contract build --package borrow-pool
stellar contract upload \
  --source deployer \
  --network testnet \
  --wasm target/wasm32v1-none/release/borrow_pool.wasm
# → prints WASM_HASH
```

## Step 2 — Deploy contract, capture the id

```bash
stellar contract deploy \
  --source deployer \
  --network testnet \
  --wasm-hash $WASM_HASH
# → prints CONTRACT_ID
```

Write `CONTRACT_ID` into `.env.local` as
`NEXT_PUBLIC_STELLAR_SHIELD_CONTRACT_ID`.

## Step 3 — Initialize with admin + reflector + rate + risk

```bash
stellar contract invoke \
  --source deployer --network testnet \
  --id $CONTRACT_ID -- \
  initialize_shielded \
    --admin <admin_address> \
    --reflector CCYOZJCOPG34LLQQ7N24YXBM7LL62R7ONMZ3G6WZAAYPB5OYKOMJRN63 \
    --rate '{"base_apr_bps":200,"slope_apr_bps":1500,"reserve_factor_bps":1000,"seconds_per_year":31536000}' \
    --risk '{"hf_min_bps":12500,"liquidation_bonus_bps":500,"liquidation_threshold_bps":8500,"max_ltv_bps":6250}'
```

## Step 4 — Register SEP-41 token per shielded asset

```bash
# XLM
stellar contract invoke --source deployer --network testnet --id $CONTRACT_ID -- \
  set_reserve --asset XLM --token_contract CDLZFC3SYJYDZT7K67VZ75HPJVIEUVNIXF47ZG2FB2RMQQVU2HHGCYSC

# Repeat for USDC + EURC with each asset's SAC / SEP-41 contract id.
```

## Step 5 — Register market pairs

```bash
for M in \
  "USDC_XLM|USDC|XLM" "XLM_USDC|XLM|USDC" \
  "EURC_USDC|EURC|USDC" "USDC_EURC|USDC|EURC" \
  "EURC_XLM|EURC|XLM" "XLM_EURC|XLM|EURC"; do
  IFS='|' read -r KEY B C <<< "$M"
  stellar contract invoke --source deployer --network testnet --id $CONTRACT_ID -- \
    register_market --market "{\"key\":\"$KEY\",\"borrow_symbol\":\"$B\",\"collateral_symbol\":\"$C\"}"
done
```

## Step 6 — Publish the liquidation-service pubkey (Track A + G-full)

Generate the X25519 keypair the service will use. Persist the seed
somewhere durable — losing it kills triage capability for every
existing bond.

```bash
SEED=0x<32-hex> bun run gen:service-key
# → prints seed, sk, pk, plus the exact invoke command to run
stellar contract invoke --source deployer --network testnet --id $CONTRACT_ID -- \
  set_liquidation_service_pk --pk <pk_hex>
```

`SEED` is optional — omit for a fresh random seed. Store `sk_hex` as
the operator's `LIQUIDATION_SERVICE_SK` env for `bun run scan:underwater`.

## Step 7 — Regenerate the frontend bindings

```bash
stellar contract bindings typescript \
  --network testnet \
  --contract-id $CONTRACT_ID \
  --output-dir /tmp/bindings \
  --overwrite
printf '%s\n%s\n' \
  '// Auto-generated by `stellar contract bindings typescript`.' \
  '/* eslint-disable @typescript-eslint/no-unused-vars, @typescript-eslint/ban-ts-comment, @typescript-eslint/no-unsafe-declaration-merging */' \
  > /tmp/hdr.txt
cat /tmp/hdr.txt /tmp/bindings/src/index.ts \
  > features/protocol/bindings/borrow-pool.ts
```

## Step 8 — Verify

```bash
bun run typecheck && bun run lint && bun run test && bun run build
```

Smoke-check the deployment via the read-only CLI:

```bash
bun run scan:underwater             # watchlist mode
LIQUIDATION_SERVICE_SK=0x<sk> bun run scan:underwater   # authenticated
```

## Upgrading in place

Every change after the initial deploy uses the admin-gated `upgrade`
path so `CONTRACT_ID` + storage stay stable:

```bash
stellar contract upload --source deployer --network testnet \
  --wasm target/wasm32v1-none/release/borrow_pool.wasm
# → NEW_WASM_HASH
stellar contract invoke --source deployer --network testnet --id $CONTRACT_ID -- \
  upgrade --wasm_hash $NEW_WASM_HASH
```

Non-additive storage changes (renaming a `PersistentKey` variant,
changing struct field order) will strand existing rows. When in doubt
add a new sidecar slot instead of mutating an old one — the Track A
and Track D sidecars follow this pattern.

## Rollback

Record the previous WASM_HASH before every upgrade:

```bash
stellar contract inspect --network testnet --id $CONTRACT_ID
# → grep for CurrentContractExecutable, capture hash
```

If a broken upgrade lands, re-upload the last-known-good wasm (already
on chain, just re-`install`) and invoke `upgrade --wasm_hash
$LAST_GOOD` from the admin identity.
